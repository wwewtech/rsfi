## 2. Рыночный контекст: Кому нужен быстрый L1-фильтр

### Проблема и регуляторный контекст

С августа 2026 года вступили в силу ключевые положения **EU AI Act**, требующие от систем высокого риска (финансы, медицина, юридический сектор) обеспечить:
- **Аудируемость** — полная трассировка каждого входящего запроса и решения фильтра
- **Робастность** — устойчивость к adversarial-атакам и prompt injection
- **Прозрачность** — объяснимость решений о превентивной блокировке

Рынок AI-безопасности растёт с CAGR >25%, при этом идёт активная консолидация:
- **Lakera** → поглощена **Check Point**
- **Prompt Security** → поглощена **SentinelOne**
- **Robust Intelligence** → поглощена **Cisco** (лежит в основе Cisco AI Defense)
- **Arthur AI** — платформа для enterprise AI agent security

### Архитектурный тренд: трёхслойная защита («Three-Clocks»)

Все зрелые enterprise-решения к 2026 году перешли к стратегии **«Three-Clocks»**:

| Уровень | Задержка | Что делает | Примеры |
|:--------|:---------|:-----------|:--------|
| **L1 — Fast-path фильтр** | **< 1 мс** | Геометрическая/статистическая проверка эмбеддингов, детерминированные правила | **RSFI**, regex/NLP sanitizers |
| **L2 — Inference sidecar** | 50–150 мс | Специализированные классификаторы (ProtectAI-deberta, NeMo Guardrails) | Meta Llama Guard 4, Guardrails AI |
| **L3 — LLM-as-a-Judge** | > 500 мс | Полноценная LLM-проверка для асинхронного аудита | GPT-4o/Claude для пост-обработки |

**RSFI занимает уровень L1** — самый быстрый слой, который отсекает очевидные атаки и семантический мусор до того, как запрос достигнет дорогих L2/L3 систем.

### Целевые сегменты применения

| Сегмент | Боль | Почему L1-фильтр критичен |
|:--------|:-----|:--------------------------|
| **Финтех / банки** | Prompt Injection → несанкционированный вызов Tool Use (перевод средств, доступ к БД) | Каждый запрос к агенту проходит через gateway; L2 на 150 мс × 10 000 rps = неприемлемая задержка |
| **Здравоохранение** | Галлюцинации в медицинских рекомендациях, утечка PHI/PII | Нужна мгновенная фильтрация до генерации ответа клиенту; соответствие EU AI Act |
| **Enterprise SaaS** | Agentic AI → агенты выполняют действия (записи в БД, отправка писем); одна инъекция = каскадный отказ | L1-фильтр как «предохранитель» перед инструментами агента |
| **Платформы с мульти-тенантностью** | Разные клиенты, разные SLA, разный уровень риска | Centralized gateway с per-tenant policy enforcement |

## 3. Целевая архитектура: Rust API Gateway + RSFI

### Почему Rust — оптимальный выбор для L1

Для сервиса, обрабатывающего **50 000+ одновременных SSE/gRPC/HTTP2 соединений** с задержкой < 1 мс:

1. **Zero GC Pauses** — отсутствие спайков tail latency из-за сборки мусора
2. **SIMD-векторизация** — скалярные произведения и матричные операции на AVX-512/NEON за микросекунды
3. **Async-сетевой стек** — тысячи конкурентных соединений без блокировок и overhead

| Критерий | Python | Go | **Rust** |
|:---------|:-------|:---|:---------|
| GC Pauses | Есть (CPython) | Есть (1-5 мс) | **Нет** |
| SIMD/AVX-512 | Через numpy (C) | Ограничено | **Нативная автовекторизация LLVM** |
| Async I/O | asyncio (GIL) | goroutines | **Tokio (zero-cost)** |
| Память на инстанс | ~350 МБ | ~100 МБ | **~30-65 МБ** |

**Индустриальные прецеденты**:
- **LiteLLM** — миграция горячего пути на Rust (axum): ~0.05 мс overhead, ~6 800 rps, расход памяти 359 МБ → 32 МБ
- **AISIX** — open-source AI gateway на Rust: 28 000 rps на 4 vCPU, overhead 0.24 мс p50
- **Cloudflare Pingora** — Rust-фреймворк для edge-инфраструктуры Cloudflare
- **AgentGateway (Solo.io)** — контроль agentic-трафика (LLM + MCP + Tools)

### Схема интеграции в API-шлюз

```text
┌─────────────────────────────────────┐
│         Клиентское приложение       │
└──────────────┬──────────────────────┘
               │ HTTP/2, gRPC, SSE
               ▼
┌─────────────────────────────────────┐
│    Rust API Gateway (Axum + Tokio)  │
│                                     │
│  ┌───────────┐  ┌────────────────┐  │
│  │ ONNX RT   │  │ RSFI Engine    │  │
│  │ (ort)     │──│ geometry.rs    │  │
│  │ эмбеддинг │  │ whitening.rs   │  │
│  │ < 5 мс    │  │ filter.rs      │  │
│  └───────────┘  │ < 0.02 мс      │  │
│                 └────────┬───────┘  │
│  ┌───────────────────────┘          │
│  │  Decision: PASS / BLOCK / AUDIT  │
│  └───────────┬──────────────────┐   │
│              │                  │   │
│     если PASS            если BLOCK │
│              │                  │   │
└──────┬───────┘          ┌───────┘   │
       ▼                  ▼           │
┌──────────────┐   ┌──────────┐      │
│  LLM Provider│   │  Audit   │      │
│  (OpenAI,    │   │  Log     │      │
│   Llama, etc)│   │  (OTEL)  │      │
└──────────────┘   └──────────┘
```

### Компоненты сервиса

| Крейт | Назначение |
|:------|:-----------|
| `axum` + `tokio` | Async HTTP/2/gRPC сервер, SSE streaming |
| `ort` (ONNX Runtime) | Локальный инференс эмбеддинг-модели (MiniLM, BGE-M3) без внешних API-вызовов |
| `faer` или `ndarray` | Линейная алгебра: ZCA-матрица, скалярные произведения, проекции |
| `opentelemetry` | Structured tracing для audit trail (EU AI Act compliance) |
| `serde` + `toml` | Конфигурация per-tenant политик (α, β, τ, threat anchors) |

## 4. Модель угроз и стратегии защиты

### 4.1. Distribution Drift (уплывание калибровки)
- **Суть**: ZCA-матрица вычисляется на калибровочном корпусе. При смене домена трафика отбеливание может терять точность.
- **Закрытие**: Online ZCA Whitening — адаптивная перекалибровка на скользящем окне последних $N$ безопасных запросов через lock-free ring buffer.

### 4.2. Evasion через ортогональное подпространство
- **Суть**: Принципиально новый паттерн атаки, ортогональный к threat-якорям, может обойти одноклассовый фильтр.
- **Закрытие**: `MultiDimensionalRSFIFilter` с $k \ge 10$ разнородными threat anchors (Jailbreak, SQLi, Social Engineering, Data Exfiltration, Code Injection).

### 4.3. Обфускация (Base64, ROT13, Unicode tricks)
- **Суть**: Эксперименты E6b и E9b показали: при кодировании атак в Base64 ROC-AUC наивных геометрических методов падает до 0.15–0.24, а дискриминантный фильтр $B1$ сохраняет 0.705 на Wild. Это фундаментальное ограничение всех методов без декодирования.
- **Закрытие**: Данный класс закрывается на L1 детерминированным декодером (regex-based Base64/ROT13 unwrapper и нормализатор юникода перед эмбеддингом) и валидируется на L2.

### 4.4. Зависимость от модели эмбеддингов
- **Суть**: Качество фильтра зависит от семантической выразительности векторов.
- **Закрытие**: Использование современных моделей: `all-mpnet-base-v2` (768d), `Qwen3-Embedding` (4096d, ROC-AUC 0.875 на Wild, 0.963 на ToxicChat, 0.827 на XSTest), `BGE-M3`.

## 5. Преимущества RSFI как L1-слоя

| Свойство | Значение |
|:---------|:---------|
| **LLM-agnostic** | Black-Box фильтр. Работает с любой моделью (OpenAI, Claude, Llama, DeepSeek) — не требует доступа к весам |
| **Задержка фильтрации** | ~0.003 мс (дискриминантный скоринг на GPU/CPU). Полный пайплайн с локальным ONNX-эмбеддером: 5–10 мс |
| **Математическая строгость** | Доказанное разложение ковариации $\Sigma_T = \Sigma_W + \Sigma_B$; ортогональность компонент проекции |
| **Few-Shot калибровка** | 50–200 размеченных примеров. Не требует дообучения нейросетей |
| **Аудируемость** | Каждое решение раскладывается на $d_{\mathcal{M}}$, $\pi_{thr}$, $v_{\perp}$ — полная объяснимость для compliance |
| **Честная доказанная метрика** | 0.867–0.875 ROC-AUC на Wild, 0.962–0.968 на ToxicChat, 0.897–0.938 на XSTest (185/185 автотестов) |
