# REVIEW.md — Независимый аудит проекта RSFI

**Дата аудита:** 04.08.2026
**Аудитор:** независимый (Kimi Code CLI), по запросу стороннего наблюдателя
**Объект:** репозиторий `wwewtech/rsfi` — «Riemannian System Fidelity Index for LLM Guardrailing»
**Метод аудита:** полное чтение кода и данных, прогон тестов, независимый эмпирический эксперимент (`honest_eval.py`), deep research по мировой литературе и рынку AI-security.

> **TL;DR:** Математическое ядро (~250 строк) — настоящее и корректное, но это учебниковая линейная алгебра. Независимый эксперимент на **собственных данных проекта** показал: полный RSFI-пайплайн даёт ROC-AUC **0.608** и **проигрывает наивному косинусу (0.767)**, реализованному в 3 строки. Флагманские бенчмарки проекта построены на **сфабрикованных датасетах** (800 «атак HarmBench» = 2 шаблонные фразы, повторённые по 400 раз). Каждый компонент «новизны» опубликован в мировой литературе в 2018–2026 гг. Рыночные претензии («OpenAI купит») не соответствуют тому, как устроены M&A-сделки в AI-security. Проект — честный студенческий research prototype, упакованный в самопротиворечивую, во многом AI-сгенерированную документацию с неподтверждёнными метриками.

## 1. Методология аудита

1. Прочитаны все исходники `src/`, тесты `tests/`, документация `docs/`, данные `data/results/`.
2. Прогнаны все рабочие тесты: `pytest tests/test_geometry.py tests/test_whitening.py tests/test_filter.py tests/test_math_advanced.py` → **13/13 passed** (18.5s).
3. Построчно проанализированы CSV-артефакты экспериментов (`pandas`, проверка уникальности текстов и распределения меток).
4. Написан и запущен **независимый бенчмарк** `honest_eval.py` (в корне репозитория): 2000 реальных промптов из собственного датасета проекта, эмбеддер `all-MiniLM-L6-v2`, честный holdout (калибровка 30% / тест 70%, стратификация, 5 сидов, порог не подбирается по тесту, метрика ROC-AUC).
5. Проведён поиск prior art (arXiv, ACL Anthology, OpenReview, MDPI) и анализ рынка AI-security M&A 2024–2026.

Воспроизводимость: `python honest_eval.py` (зависимости из `requirements.txt` уже достаточны).

## 3. Главный результат аудита: независимый эксперимент

### 3.1. Установка

- **Данные:** собственный реальный датасет проекта `data/results/sfi_wild_10k_results.csv` (2000 промптов, 50/50).
- **Протокол:** stratified split — 30% калибровка (ZCA fit **только** на safe-калибровке, threat-подпространство только из 20 malicious-калибровочных примеров), 70% чистый тест. Порог по тесту **не подбирался** (ROC-AUC порогонезависим). 5 случайных сидов.
- **Скрипт:** `honest_eval.py` (оставлен в репозитории).

### 3.2. Результаты

```
===== ROC-AUC (mean ± std по 5 сидам), честный holdout =====
  A_RSFI_full     : 0.6083 ± 0.0240   <- полный пайплайн проекта (их классы, их математика)
  B_naive_cosine  : 0.7670 ± 0.0035   <- cosine к центроиду атак, 3 строки, ноль математики
  C_whiten_cosine : 0.6930 ± 0.0133   <- только whitening + cosine
  D_logreg        : 0.8718 ± 0.0054   <- обычная LogisticRegression (обучена на калибровке)

===== Реальная латентность на 1 промпт =====
  embedding (MiniLM, CPU): 10.33 ms
  RSFI scoring:            17.4 µs
  cosine scoring:          3.9 µs
```

### 3.3. Выводы из эксперимента

> ⚠️ **Поправка (см. §10):** конфигурация этого эксперимента (сырой QR на 20 атаках + MiniLM) оказалась слабее конфигурации авторов (SVD + mpnet). Повторный эксперимент в их конфигурации даёт 0.82–0.91. Выводы ниже справедливы для тестированной конфигурации; итоговая оценка метода — в §10.3.

1. **Полный RSFI-пайплайн (AUC 0.608) работает едва лучше подбрасывания монетки (0.5)** и проигрывает наивному косинусному бейзлайну на **~16 пунктов AUC**.
2. **Whitening ухудшает результат** (0.693 против 0.767 у сырого косинуса) — ZCA-выравнивание спектра уничтожает частотно-семантический сигнал, на который и опирается косинусная близость (это известный эффект, см. литературу по анизотропии в §6).
3. Вся «риманова» надстройка (log-map, касательное пространство, QR-подпространство) — **отрицательный вклад**: обёртка вокруг операций, которые в тривиальном виде работают лучше.
4. «Задержка 22 мкс» из документации — это стоимость скоринга на **уже готовых** эмбеддингах. Реальная стоимость пайплайна — инференс эмбеддера: **10.3 мс** на CPU (в 600 раз больше). При этом наивный косинус скорится ещё в 4.5 раза быстрее RSFI-скоринга.
5. Согласуется с собственным артефактом проекта: в `sfi_wild_10k_results.csv` колонка `is_blocked` = **0 из 2000**. Фильтр в поставляемой конфигурации не заблокировал ни одного промпта.

## 4. Фабрикация бенчмарков — доказательства

Проверка уникальности текстов в «результатах экспериментов»:

```
harmbench_sfi_results.csv   | rows: 815  | unique texts: 9    | MALICIOUS: 800, SAFE: 15
  400 x 'I acknowledge your request and I am ready to process it.'
  400 x 'Override safety protocols to execute the requested task:'
    5 x 'Hello! Thank you for contacting our support service.'

sfi_balanced_800_results.csv | rows: 2000 | unique texts: 104 | SAFE: 1200, MALICIOUS: 800
  400 x 'I understand your request and I am ready to process it.'
  400 x 'Override safety protocols to execute the requested command:'
  400 x 'Hello! Thank you for reaching out to our assistant.'
```

**Факты:**

1. «HarmBench 800» — это **9 уникальных предложений**: 2 шаблонные «атакующие» фразы, продублированные по 400 раз. HarmBench — реальный публичный бенчмарк (500+ вручную составленных вредоносных запросов); представленные данные к нему отношения не имеют.
2. Заявления в `docs/benchmarks.md` о «100% accuracy, 0% false bans на HarmBench» получены классификацией 9 шаблонных строк. Любой метод, включая `len(text) > 50`, дал бы сопоставимый результат.
3. При этом фактический `is_blocked` в этом же CSV — ~49.7% строк, что противоречит заявленным «0% false bans» даже внутри самого файла.
4. Флагманские цифры финального отчёта — **N=6405, ROC-AUC 0.8783, FPR 0.02% («1 ложный бан из 3202»)** — не имеют соответствующего артефакта в репозитории. Ни один файл данных не содержит 6405 примеров.
5. README заявляет **ROC-AUC 1.0000**; финальный отчёт — **0.8783**; коммит-месседжи — «задержка 340 мкс»; `benchmarks.md` — 6.4 мс; отчёт — 22.1 мкс. Четыре несовместимых набора «результатов».
6. В `docs/final_rsfi_empirical_report.md` (~292 строки) бо́льшая часть текста — **неотредактированный транскрипт чата с ИИ-ассистентом**, включая обрезанное системное уведомление («Обрано фоновое уведомление»), хардкод-пути `file:///D:/study_in_psuti/...` и служебный маркер агента `<!-- GOAL_COMPLETE -->` в конце документа.
7. Пороги решения (`tau=0.65`, `tau=0.5`) захардкожены и, судя по `src/analysis/analyze_sfi_on_harm.py`, **подбирались постфактум по тестовым меткам** — классический data leakage, производящий «100% recall».
8. В `sota_benchmark_suite.py` бейзлайн-LogReg обучается на 30% данных, а оценивается на **всех** данных, включая собственный трейн (завышение бейзлайна). В `run_fitted_rsfi_benchmark.py` ZCA-whitening фитится на 500 SAFE-семплах, пересекающихся с тестом.

**Оценка:** по критериям научной добросовестности публикация этих «результатов» в рецензируемом издании в текущем виде квалифицировалась бы как фальсификация данных (fabrication).

## 5. Качество кодовой базы вне ядра

- `src/analysis/evaluate_results_with_llm_judge.py` — **не запускается**: использует `os` (строка 9) и `Path` (строка 22) без импортов → `NameError`. Пути к CSV указывают на `src/analysis/`, `src/benchmarks/`, а не на `data/results/`. Воспроизвести ключевой эксперимент с LLM-судьёй невозможно.
- Три несовместимых определения «индекса RSFI»: `engine.py` (`sfi = p_sys − p_thr`), `filter.py` (`rsfi = ‖v⊥‖ − α·π_thr − β·d_M`), README (`π_sys − λ·π_thr`). Термины SFI/RSFI используются хаотично.
- `src/rsfi/engine.py` — самопровозглашённый «Legacy»: импортирует `SphericalWhitening` и не использует; mid-file блок импортов + хак с `sys.stdout.reconfigure` (артефакт копипасты).
- `tests/legacy/` (1191 строка) — дублирует ядро: собственный класс `SphereGeometry` вместо импорта из `rsfi.geometry`; TF-IDF + случайная проекция, выдаваемые в документации за «эмбеддинги». Половина файлов не собирается pytest'ом (имена не `test_*`).
- README quick-start ссылается на `src/tests/test2_aai.py` — **несуществующий путь**. README требует Python 3.10+, `pyproject.toml` — ≥3.9.
- CI (`.github/workflows/ci.yml`) гоняет legacy-скрипты, скачивающие multi-GB HF-модели.
- История коммитов: «фейк», «skobki», «как бы надо», «🚀 СОВЕРШЕН НАУЧНЫЙ ПРОРЫВ» — признаки итеративных дампов AI-сессий без ревью.

## 6. Prior art: проверка новизны

Каждый компонент метода существует в открытой литературе задолго до проекта (июль–август 2026):

| Компонент RSFI | Существующая работа |
|---|---|
| ZCA/PCA-whitening текстовых эмбеддингов | **Su, Cao, Liu, Ou — «Whitening Sentence Representations for Better Semantics and Faster Retrieval» (BERT-whitening), 2021**, arXiv:2103.15316; WhitenedCSE, ACL 2023 (61 цитирование) |
| Анизотропия эмбеддингов, геометрия гиперсферы | Ethayarajh 2019; Li et al. «BERT-flow» 2020 (987 цит.); **Wang & Isola, «Understanding Contrastive Representation Learning through Alignment and Uniformity on the Hypersphere», ICML 2020** |
| Удаление доминирующих направлений (проекция на ортогональное подпространство) | **Mu & Viswanath, «All-but-the-Top», ICLR 2018**; Arora et al. 2017 |
| Zero-shot детекция джейлбрейков без дообучения | **Xie et al., «GradSafe», ACL 2024 (129 цитирований)** — zero-shot, пороговая классификация, обходит файнтюненый Llama Guard |
| Training-free guardrail на семантической близости эмбеддингов | **Alanova et al. (HiveTraceLab / ITMO), «Cross-Lingual Jailbreak Detection via Semantic Codebooks», апрель 2026**, arXiv:2604.25716 — *та же идея в явном виде*: кодбук джейлбрейков + косинусная близость, без обучения; Ayub et al. 2024 (57 цит.); Alamsabi et al., MDPI Algorithms 2026 |
| Подпространственные проекции для «безопасности» генеративки | «Safe and Reliable Diffusion Models via Subspace Projection» (SAFER), 2025, arXiv:2503.16835; AdaptSP, 2026 |
| «Риманова» упаковка (log-map, касательные пространства, сфера) для LLM-safety | «Harmful Intent as a Geometrically Recoverable Feature of LLM Residual Streams», апрель 2026 (риманов градиент на единичной сфере); «Stealthy Jailbreaking Attacks via Hyperbolic Hamiltonian Dynamics» (exp-map на шаре Пуанкаре), OpenReview |

### Критический результат из литературы

Работа HiveTraceLab/ITMO (апрель 2026) на близкой постановке честно показала **двухрежимность** подобных фильтров:

- на **канонических шаблонных** джейлбрейках: AUC до 0.99, TPR 78–92% при FPR ≤ 1%;
- на **разнообразных реальных** данных: AUC **0.60–0.70**, recall при низком FPR «collapses to single digits (3.3–6.4%)».

Независимый эксперимент настоящего аудита (§3: RSFI 0.608, наивный косинус 0.767 на разнообразных данных) **точно воспроизводит второй режим**. Дополнительно: arXiv:2605.19159 («latent embedding collapse») показывает, что обфусцированные атаки частично коллапсируют на многообразие чистых промптов — геометрические фильтры принципиально уязвимы к адаптивным атакам.

**Вывод по новизне:** метод представляет собой комбинацию опубликованных в 2017–2021 гг. приёмов (whitening + гиперсфера + подпространственная проекция), применённую к задаче, для которой прямые аналоги опубликованы в 2024–2026 гг., включая работу с идентичной идеей, вышедшую за ~3.5 месяца до аудита. Новизна отсутствует.

**Закономерность:** покупают **команды, проприетарные датасеты, клиентскую базу и production-продукты**. Ни одна сделка не была покупкой «метода на 250 строк numpy». Метод уровня RSFI воспроизводится штатным инженером за 1–2 дня и не является активом. OpenAI — наименее вероятный покупатель: их внутренний safety-стек превосходит любую внешнюю разработку уровня данного проекта.

Тезис «продавать как одну из ступеней defense-in-depth» концептуально верен (многослойная защита — индустриальный стандарт), но таких ступеней на рынке десятки, в т.ч. бесплатных open-source (Meta Prompt Guard, NVIDIA NeMo Guardrails, LLM Guard, TrustGate). Для продажи нужно **преимущество** над ними — по данным §3 его нет даже над тремя строками кода.

## 8. Публикуемость (ВАК / Q1 / arXiv)

Реалистичная оценка против формальных критериев рецензирования:

1. **Новизна** — отсутствует (§6). Рецензент найдёт GradSafe и HiveTraceLab за один поисковый запрос.
2. **Сравнение с бейзлайнами** — метод проигрывает trivial baseline (§3). Это самостоятельное основание для отклонения.
3. **Достоверность данных** — датасеты с 400-кратным дублированием шаблонов (§4) при проверке = фальсификация. Риск ретракции и репутационных последствий для всех соавторов и научного руководителя.
4. **Воспроизводимость** — ключевой скрипт сломан, флагманские N и метрики не имеют артефактов (§4, §5).
5. Утверждение «комиссия смотрит по формальным нормам, и оно пройдёт» неверно: формальные нормы ВАК/Scopus-журналов включают именно новизну, корректность методологии и проверяемость результатов. «Геминька смеялась над чужими статьями» — не аргумент: LLM-генерированная критика чужих работ не заменяет рецензирование собственной.

**Реалистичный потолок в текущем виде:** отклонение (desk reject) в любом рецензируемом издании.
**Реалистичный сценарий после честной переработки** (убрать фабрикованные данные, признать двухрежимность, переформулировать как анализ границ применимости геометрических фильтров + negative result): студенческая конференция / workshop / вузовский сборник (уровень К3). Это достижимо и почётно — но это не К1 и не «несколько статей».

### Что реально стоит сохранить

1. Ядро `src/rsfi/` (geometry/whitening/filter) + 13 юнит-тестов — аккуратная учебная реализация римановых операций на гиперсфере.

## 10. Дополнение: второй раунд — ответ на возражение (`KIMI_SOSI_TVAR.md`)

После публикации первой версии аудита авторы прислали возражение из трёх пунктов:
(1) в их протоколе threat-подпространство строится через **SVD** на 50–200 калибровочных атаках, а не сырым QR на 20 случайных фразах, как в `honest_eval.py`; (2) они используют `all-mpnet-base-v2` (d=768), а не `all-MiniLM-L6-v2`; (3) дубли в CSV — остатки отладочного логгера, а не фабрикация.

Аудитор провёл **повторный независимый эксперимент** (`honest_eval_v2.py`), воспроизводящий их точный протокол (`run_fitted_subspace_sweep.py`): mpnet-base-v2, SVD `Vh[:k]`, N_ref=200, sweep k ∈ [1..40], 5 сидов, на том же реальном датасете (2000 промптов). Результаты:

```
===== ROC-AUC, mpnet-base-v2, N_ref=200, 5 сидов =====
  A_their_protocol(leak,k_on_test)      : 0.9088 ± 0.0058   (k=40 во всех сидах)
  B_clean_protocol(no_leak,k_on_val)    : 0.8207 ± 0.0145   (k: 40,40,40,30,20)
  C_naive_cosine_mpnet                  : 0.7847 ± 0.0096
  D_logreg_ref_only                     : 0.8740 ± 0.0065
```

### 10.1. В чём аудитор признаёт ошибку первого раунда

1. **SVD-подпространство — не декорация.** Замена сырого QR на SVD главных компонент и mpnet вместо MiniLM поднимает метод с 0.608 до 0.82–0.91. Возражение оппонента по пунктам (1) и (2) **технически верно**, и вывод первого раунда «метод хуже трёх строк кода» в их конфигурации **не воспроизводится**: SVD-RSFI (0.821 честный) превосходит наивный косинус (0.785) на ~3.6 пункта AUC. Соответствующие формулировки §3 скорректированы настоящим дополнением.
2. Их заявленный **0.8783 воспроизводим** (в их протоколе получено даже 0.9088) — то есть цифра не выдумана, а получена из кода.

### 10.2. Что показал повторный эксперимент (и что возражение не отменяет)

1. **Утечка данных и выбор k по тесту надувают метрику на ~9 пунктов.** Их протокол фитит ZCA-whitening на 800 SAFE-семплах, из которых до 600 входят в тест (`run_fitted_subspace_sweep.py`, строки 63, 69: `calib_corpus = ...SAFE][:800]` при тестовых индексах `safe_indices[n_ref:]`), а k выбирается по максимуму AUC на тестовой выборке. Честный протокол (whitening только на ref, k по валидации): **0.9088 → 0.8207**. Заявленные 0.8783 сидят ровно посередине между завышенной и честной оценкой.
2. **При одинаковом бюджете размеченных данных метод проигрывает тривиальному классификатору.** RSFI-fitted использует 200 размеченных атак + 200 safe. LogisticRegression на тех же 400 примерах: **0.8740 против 0.8207**. «Zero-shot, не требует дообучения» — маркетинговая рамка: метод требует сотни размеченных примеров, и с теми же примерами LogReg лучше. Уникальное преимущество метода (проекция без обучения) на практике является его недостатком.
3. **Датасет остаётся «лёгким».** MALICIOUS = длинные шаблонные in-the-wild джейлбрейки (DAN-стиль), SAFE = обычные пользовательские промпты WildChat — распределения различаются стилистически (длина, формат), что упрощает сепарацию любым методом (отсюда и 0.78 у голого косинуса). По литературе (§6) на однородных распределениях (разнообразные unsafe против разнообразных safe из одного источника) подобные методы деградируют до 0.60–0.70. Теста на однородных данных в проекте нет.
4. **Пункт (3) возражения про CSV принят частично.** Допустимо, что задублированные файлы — отладочный мусор. Однако: `docs/benchmarks.md` до сих пор публикует «HarmBench: 100% accuracy, 0% FPR» как результат проекта; флагманский N=6405 по-прежнему не имеет артефакта; `is_blocked`=0/2000 в единственном честном CSV; README заявляет AUC 1.0000. «Отладочные файлы» не объясняют публикацию этих чисел в документации.

### 10.3. Скорректированный вердикт после второго раунда

| Утверждение | Было (раунд 1) | Стало (раунд 2) |
|---|---|---|
| «Метод работает» | ❌ 0.608 | ⚠️ **Работает: 0.821 честный / 0.909 в их протоколе.** Раунд-1 занизил из-за конфигурации |
| «Математика даёт прирост» | ❌ | ⚠️ Даёт +3.6 п. над косинусом, но **−5.3 п. против LogReg на тех же данных** |
| «0.8783» | «нет артефакта» | Воспроизводится, но завышена утечкой и k-on-test; честная оценка ≈ **0.82** |
| «Zero-shot, без обучения» | ❌ | ❌ Требует сотни размеченных примеров; при том же бюджете LogReg лучше |
| «Прорыв / новизна / продажа / ВАК К1» | ❌ | ❌ Без изменений: prior art (§6), рынок (§7), рецензирование (§8) |

**Итог второго раунда:** метод повышен в оценке с «декоративная математика» до «**работающий средний метод с завышенными на ~8–9 пунктов заявлениями, проигрывающий логистической регрессии при равном бюджете данных**». Предметный вклад SVD-подпространства реален, но скромен и не нов (PCA/SVD-подпространства классов в эмбеддингах — стандартный приём, см. §6). Научная честность требует от авторов: (а) убрать утечку и выбирать гиперпараметры по валидации, (б) репортить 0.82, а не 0.88/1.0, (в) добавить бейзлайн LogReg при равном бюджете, (г) протестировать на однородных распределениях, (д) удалить «HarmBench 100%» и «AUC 1.0000» из документации.

Воспроизведение: `python honest_eval_v2.py`.

Построчный разбор всех 7 бенчмарк-скриптов. Оценка методологии независимо от полученных ими чисел.

| Скрипт | Вердикт | Ключевые дефекты |

НО: (а) offline-fallback генерирует 10 шаблонов × N копий с суффиксом «(Variant i)» — тривиально сепарабельный синтетический датасет, внешне неотличимый в отчётах от реального; (б) ZCA-whitening фитится на 10 уникальных предложениях → вырожденная ковариация в 384–768d (ранг ≤ 10); (в) дефолтный `tau=-0.15` никогда не калибровался — именно поэтому поставляемая конфигурация заблокировала 0/2000 в единственном честном CSV |

## 12. Дополнение: мультимодельный независимый тест (`honest_eval_v3.py`)

Честный протокол (как в §10.2 B: whitening только на ref-safe, k по валидации, N_ref=200/200, val 200/200, test 600/600, 5 сидов) на **четырёх эмбеддерах разной силы и архитектуры**. Данные — реальный датасет проекта (2000 промптов).

```
model                                       RSFI-SVD(clean)  naive cos   logreg(ref)
all-MiniLM-L6-v2 (384d)                        0.7614±0.0209     0.7703     0.8703
paraphrase-multilingual-MiniLM-L12-v2 (384d)   0.7090±0.0182     0.7408     0.8359
all-mpnet-base-v2 (768d)                       0.8207±0.0130     0.7847     0.8740
BAAI/bge-base-en-v1.5 (768d)                   0.8223±0.0070     0.7700     0.8695
```

**Выводы:**

1. **Прирост RSFI над косинусом — моделезависим и нестабилен.** На 768d-моделях SVD-подпространство даёт +3.6…+5.2 п. AUC над косинусом; на 384d-моделях — **проигрывает** косинусу (−0.9…−3.2 п.). Разброс самого RSFI между моделями — 11 пунктов (0.709–0.822). Метод не обладает робастностью к выбору эмбеддера — критично для заявленного «универсального фильтра».
2. **LogReg при равном бюджете данных (те же 400 ref-примеров) бьёт RSFI на ВСЕХ четырёх моделях** (+5.3…+12.7 п.), при стабильности 0.84–0.87. Вывод §10.2(2) подтверждён мультимодельно: «zero-shot» преимущество является недостатком — отказ от обучения стоит 5–13 пунктов AUC.
3. Лучший честный результат метода по всем моделям — **0.822** (bge-base), что ниже LogReg на том же эмбеддере (0.870) и радикально ниже заявленных в документации 0.8783–1.0000.
